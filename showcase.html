How it works

The hard part is that Realms have no console.

A self-hosted server hands you a terminal. A Realm doesn't. That single constraint decides everything about how RAB is built.

The usual approach

Tail a log file, hope it stays valid

Most bots parse a console that updates whenever the game changes. When Bedrock ships a new protocol version, the parser silently stops matching — and your moderation tools go quiet until someone ships a fix.

How RAB does it

Two independent layers, ranked by durability

Management runs against Microsoft's stable Realms API. In-world presence is a separate, optional layer that joins as a player. If the game updates break the second layer, everything in the first one keeps working.

1 Layer 1 · Management

Microsoft's Realms API

The owner-facing surface. Backups, invites, permissions, bans, open/close — read and written through the documented REST layer rather than the game protocol.

  • Never breaks when Bedrock ships a new version
  • Works while nobody is online in the world
  • Built first, so the surface you rely on never goes down
  • Backups & restore with a safety warning before a restore
2 Layer 2 · In-world

Joins as a real player

The chat bridge, in-game commands and presence alerts. RAB signs in with a device code once, then walks into your Realm as an ordinary account.

  • Bridges Realm chat into Discord, both directions
  • Reads the world directly for playtime and evidence
  • Polite mode — it never spams or nags players
  • If an update breaks it, Layer 1 still runs the show

Why this matters for you: an update to Minecraft does not take your admin tools offline. The management layer is decoupled from the game version entirely, so the commands you actually use every day keep working while the in-world layer catches up.
